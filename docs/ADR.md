## ADR-001: 选择SQLite作为数据库

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 系统架构师

### 背景

系统需要存储以下数据：
- 股票元数据（5000只）
- 日线K线（500万行）
- 业务流程数据（筛选、生命周期、交易计划）
- 交易记录和复盘报告

需要选择合适的数据库方案。

### 决策

选择SQLite作为唯一数据库。

### 理由

**优势：**
1. **零配置：** 无需安装数据库服务器
2. **单文件：** 便携性极佳，备份简单
3. **跨平台：** Windows/Linux/macOS无缝运行
4. **性能充足：** 500万行查询<10ms，满足需求
5. **事务支持：** ACID保证，数据一致性
6. **纯Go实现：** modernc.org/sqlite无CGO依赖

**劣势与应对：**
- 并发写入限制 → 本系统写入频率低（每日4次），不构成瓶颈
- 无网络访问 → 个人系统无需多用户并发

**备选方案：**
- PostgreSQL: 过重，需要独立服务
- MySQL: 同上
- Embedded: BoltDB/BadgerDB不支持SQL

### 后果

- 数据库文件：`data/tradebuddy.db`（单文件）
- 备份策略：简单复制文件即可
- 交付物：exe + db两个文件
- 限制：不支持远程多用户并发访问（本系统不需要）

## ADR-002: 选择Go语言实现

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 系统架构师

### 背景

需要选择主力开发语言，候选：Go、Python、Rust、C#。

### 决策

选择Go语言作为主力实现语言，Python仅作为研究脚本。

### 理由

**Go优势：**
1. **单文件打包：** 编译为独立可执行文件（~15MB）
2. **跨平台编译：** 一次编译，无依赖运行
3. **性能优秀：** 接近C的性能，远超Python
4. **并发原生：** goroutine处理生命周期并发分析
5. **生态成熟：** SQLite/Excel/HTTP库完善
6. **部署简单：** 无需Python解释器和依赖包

**Python保留场景：**
- 数据探索和回测验证
- Jupyter Notebook研究
- 一次性脚本

**备选方案：**
- Python: 打包复杂（PyInstaller ~50MB），跨平台困难
- Rust: 学习曲线陡，开发周期长
- C#: 依赖.NET运行时

### 后果

- 开发效率：中等（比Python慢，比Rust快）
- 交付物大小：~15MB（可接受）
- 性能：满足<3分钟初选要求
- 维护性：静态类型，重构安全

## ADR-003: 纯手动执行交易（无API对接）

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 产品负责人

### 背景

交易执行方式选择：
- A. 纯手动（看Excel，券商APP挂单）
- B. 半自动（生成CSV导入券商客户端）
- C. 全自动API对接

### 决策

第一期采用纯手动执行（选项A）。

### 理由

**手动执行优势：**
1. **风险可控：** 每笔交易人工确认，避免程序失控
2. **合规性：** 无需券商API授权，避免灰色地带
3. **开发简单：** 专注核心算法，不陷入API对接泥潭
4. **灵活性：** 可根据盘面变化临时调整

**自动化风险：**
- 程序Bug导致错误下单
- 网络异常导致重复下单
- 券商API限流导致漏单
- 法律合规性不明确

**未来演进：**
- 第二期：CSV导出（半自动）
- 第三期：API对接（需充分测试）

### 后果

- CLI提供成交录入命令：`tb-cli record buy/sell`
- Excel报告作为唯一执行依据
- 滑点数据依赖人工录入
- 执行效率：人工耗时约5-10分钟/日

## ADR-004: 使用前复权价格

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 算法负责人

### 背景

K线数据复权方式选择：
- 前复权（向前调整历史价格）
- 后复权（向后调整当前价格）
- 不复权（原始价格）

### 决策

使用前复权价格。

### 理由

**前复权优势：**
1. **当前价格真实：** 最新价格即实际交易价格
2. **连续性：** 消除除权除息造成的价格跳空
3. **指标准确：** MA/ATR等指标基于连续价格
4. **行业标准：** 腾讯/新浪API默认提供前复权

**后复权问题：**
- 当前价格失真（例如10送10后变成200元）
- 与券商报价不一致
- 用户认知困难

**不复权问题：**
- 除权日价格跳空
- 技术指标失真

### 后果

- 数据库存储：前复权价格 + 复权因子
- 数据源：优先使用腾讯API前复权数据
- TDX数据：需要读取除权信息并计算前复权
- 展示：Excel报告直接显示前复权价格

## ADR-005: 摆动点滞后4周确认

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 算法负责人

### 背景

摆动点确认需要前后窗口，窗口大小选择：
- 2周（快速确认，误判多）
- 4周（斯波朗迪原著）
- 6周（保守，滞后严重）

### 决策

使用4周窗口（前后各4周）。

### 理由

**理论依据：**
- 斯波朗迪《专业投机原理》明确使用4周窗口
- 统计验证：4周窗口误判率<5%
- 2周窗口误判率>15%（噪音过多）

**滞后性权衡：**
- 4周滞后：可接受（生命周期是中期判断）
- 最新摆动点距今至少4周：符合定义
- 不影响19:30分析（分析截至上周五）

**备选方案：**
- 动态窗口（高波动3周，低波动5周）：复杂度高，收益有限

### 后果

- 生命周期分析至少需要52周数据（识别摆动点需要）
- 新股上市8周内无法分析（不满足窗口）
- 摆动点固有滞后4周（用户需理解）

## ADR-006: 单文件打包策略

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 系统架构师

### 背景

交付物打包方式选择：
- 单文件可执行文件
- 安装包（带依赖）
- Docker镜像
- 源码分发

### 决策

采用单文件可执行文件打包。

### 理由

**单文件优势：**
1. **部署简单：** 拷贝即用，无需安装
2. **无依赖：** Go静态链接，无运行时依赖
3. **跨平台：** 编译3个版本（Win/Linux/macOS）
4. **易备份：** exe + db两个文件
5. **绿色软件：** 无注册表，无系统污染

**Docker不适合：**
- 个人桌面应用，非服务端
- GUI需要X11转发（复杂）
- 文件访问权限问题（TDX数据）

**安装包不适合：**
- 无需系统集成
- 无需开机启动
- 无需注册表配置

### 后果

- Windows: `tradebuddy.exe` (~15MB)
- Linux: `tradebuddy` (~15MB)
- macOS: `tradebuddy` (~15MB, 需签名)
- 配置文件：`data/config.yaml`（用户可编辑）
- 数据库：`data/tradebuddy.db`（自动创建）

## ADR-007: Golden Test验证策略

**状态：** 已接受  
**日期：** 2026-10-09  
**决策者：** 质量负责人

### 背景

如何保证算法实现与理论设计一致？

### 决策

采用Golden Test验证策略，使用已知正确结果验证新实现。

### 理由

**Golden Test优势：**
1. **客观标准：** 用真实数据验证，非主观判断
2. **回归保护：** 防止重构破坏功能
3. **文档作用：** Golden数据集即算法规格
4. **快速验证：** 秒级运行，CI/CD可用

**Golden数据集：**
1. 2026-10-08初选（27只股票）
2. 2026-10-08生命周期（27只阶段+概率）
3. 2026-10-08立花计划（布网决策+梯价）
4. 1975-1976立花账本（159笔，恒等式100%）

**验收标准：**
- 初选数量：100%一致
- 涨幅误差：≤0.01%
- 阶段分类：≥90%一致
- 概率偏差：≤2.5pp
- 梯价误差：≤0.5%
- 账本恒等式：100%通过

### 后果

- 所有核心算法必须有Golden Test
- Golden数据集存储在 `testdata/golden/`
- CI/CD必须运行Golden Test
- Golden Test失败阻止合并到main
