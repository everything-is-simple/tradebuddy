# TradeBuddy 需求规格说明

> Requirements Specification  
> Version 1.0 - 2026-10-09

---

## 一、项目概述

### 1.1 项目背景

个人A股投资者需要一个**从选股到交易到复盘的完整闭环系统**，将经典交易理论（欧奈尔、立花义正、斯波朗迪等）转化为可执行的量化策略，帮助进行系统化的交易决策和风险管理。

### 1.2 核心问题

**现状：**
- 手工选股耗时且容易遗漏
- 缺乏系统化的生命周期判断
- 交易计划不连贯，执行随意
- 缺乏完整的交易记录和复盘

**目标：**
- 每日自动筛选强势突破股
- 统计概率驱动的生命周期分析
- 标准化的交易计划和跟踪池管理
- 完整的交易记录和质量评价

### 1.3 用户画像

**主要用户：** 个人A股趋势/动量交易者

**特征：**
- 熟悉技术分析和量化交易概念
- 偏好价量原始数据，而非过度拟合的指标
- 需要统计概率支持决策，而非经验直觉
- 接受高度自动化，但执行环节需要人工确认（券商APP手动挂单）

## 二、功能需求

### 2.1 核心业务流程

```
输入                    处理                       输出
─────────────────────────────────────────────────────────
全市场日线数据      →  19:00 强势股初选      →  备选清单Excel
                       (涨幅>6% + 创20日新高
                        + 周月线趋势过滤)

备选清单           →  19:30 生命周期分析    →  阶段+存活概率Excel
                       (摆动结构九阶段
                        + 统计概率表查询)

备选清单           →  20:00 立花交易计划    →  买卖点+跟踪池Excel
+ 生命周期阶段         (回档布网 + 梯价
                        + 止损 + 仓位计算)

Excel交易计划      →  人工执行              →  成交记录录入
                       (看Excel → 券商APP
                        → tb-cli record)

成交记录           →  15:30 每日复盘        →  复盘报告Excel
+ 跟踪池更新           (滑点分析 + 账本校验
                        + 权益曲线)
```

### 2.2 功能模块详细需求

#### 2.2.1 强势股初选（Screener）

**执行时间：** 每日 19:00  
**输入数据：** 全市场日线K线  
**筛选条件：**

| 条件 | 具体规则 | 理论依据 |
|------|----------|----------|
| 条件A | 当日涨幅 > 6%（严格大于） | 欧奈尔N=新高+突破日强度 |
| 条件B | 当日最高价 > 前20个交易日最高价（前复权） | 达瓦斯箱体突破 |
| 条件C | 周线趋势：收盘 > 周MA30 且 MA30不向下 且 周MACD DIF≥DEA | Minervini趋势模板 |
| 条件C | 月线趋势：收盘 > 月MA10 且 MA10不向下 且 月MACD DIF≥DEA | 同上 |

**剔除规则：**
- ST/*ST/退市整理股
- 上市 < 21个交易日
- 北交所股票
- 当日停牌

**输出格式：**
- Excel文件：`reports/screen/A股备选清单_YYYY-MM-DD.xlsx`
- 包含字段：代码、名称、板块、当日涨幅%、收盘价、最高价、成交量、换手率、距52周高点%、周MA30、月MA10

**验证标准：**
- Golden test: 2026-10-08应产出27只股票（已有证据文件）
- 数据一致性：与历史Python版本结果100%一致

#### 2.2.2 生命周期分析（Lifecycle）

**执行时间：** 每日 19:30  
**输入数据：** 19:00备选清单 + 个股周线数据（320周）  
**分析方法：**

**主引擎：摆动点结构（无均线依赖）**
```
1. 识别摆动点
   - 摆动高点：某周高点为其前后各4周窗口内唯一最高
   - 摆动低点：某周低点为其前后各4周窗口内唯一最低
   - 滞后4周为固有属性（需要右侧4周确认）

2. 判定结构
   - 上升：最近两高点抬高 且 最近两低点抬高
   - 下跌：最近两高点走低 且 最近两低点走低
   - 无趋势：其他情况

3. 九类阶段分类
   1·筑底早期 / 1·筑底后期 / 1·区间震荡
   1→2·突破尝试（收盘突破上一摆动高点但结构未确认）
   2·早期 / 2·中期 / 2·晚期
   3·做头 / 3·高位整理
   4·下跌

4. 量能VR13
   VR13 = 近13周上涨周成交量合计 / 下跌周成交量合计
   ≥1.2 放量 / 0.9~1.2 平量 / <0.9 缩量

5. 统计概率查询
   查表：(阶段 × 量能) → 8周存活概率
   - 数据源：概率表JSON（22.8万面板观测）
   - 输出：存活概率 + Wilson 95%置信区间 + 样本量
```

**第二视角：±25%行情生命**
```
- 生命确认：周收盘自阶段低点反弹 ≥ +25%
- 生命终结：自阶段高点回撤 ≥ −25%
- 细分阶段：②上升 / ②上升·回档 / ③做头 / ①筑底·回升中 / ④下跌
- 生命存活8周%：S(age+8)/S(age)（Kaplan-Meier）
```

**输出格式：**
- Excel文件：`reports/lifecycle/生命周期分析_YYYY-MM-DD.xlsx`
- 包含字段：代码、名称、阶段、量能、VR13、52周位置、存活概率%、置信区间、样本量、±25%生命阶段

**质量要求：**
- 概率必须是统计估计，附样本量和置信区间
- 样本外校准误差 ≤ 2.5pp（已验证基线）
- 两口径分歧时如实报告，不强行统一

#### 2.2.3 立花交易计划（Tachibana）

**执行时间：** 每日 20:00  
**输入数据：** 19:00备选清单 + 19:30生命周期 + 个股日线数据  
**核心逻辑：**

**1. 可交易性过滤**
```
布网：摆动阶段 ∈ {2·早期, 2·中期, 1→2·突破尝试}
观察：2·晚期（延伸过度）
排除：1*/3*/4·下跌 / 数据不足
```

**2. 回档带判定**
```
MA20  = 近20日收盘价移动平均
ATR14 = 近14日真实波幅平均
z     = (MA20 - 现价) / ATR14

回档带：0.8 ≤ z ≤ 2.5
z > 2.5：回档过深，排除
```

**3. 买入梯价（分批建仓）**
```
梯① = MA20 - 0.75 × ATR14
梯② = MA20 - 1.50 × ATR14
梯③ = MA20 - 2.25 × ATR14

梯距参数来自立花1975-76账本校验：
中位梯距 = 0.37 ATR
```

**4. 止损与止盈**
```
止损价 = max(梯③ - 1 × ATR14, MA60)
上沿价 = MA20 + 2 × ATR14（第一止盈档）
```

**5. 仓位计算**
```
参考资金 = 100万
单股风险预算 = 1%（1万元）
梯档风险配比 = 40% / 30% / 30%

单股风险 = 现价 - 止损价
总股数 = 风险预算 / 单股风险

梯①股数 = (总股数 × 40%) 向下取整100股
梯②股数 = (总股数 × 30%) 向下取整100股
梯③股数 = (总股数 × 30%) 向下取整100股

约束：
- 单股名义市值上限 20万
- 止损价 ≥ 某梯价时，该梯作废
```

**6. 跟踪池状态机**
```
加入时：status = active, tier*_status = pending

成交判定：当日最低价 ≤ 梯价 → filled
止损判定：当日最低价 ≤ 止损价 → stopped
止盈提醒：当日最高价 ≥ 上沿价 → 推送提醒
过期规则：40自然日无成交 → expired

跟踪池上限：120条 FIFO
参数冻结：加入后梯价/止损不再追改
```

**输出格式：**
- Excel文件：`reports/tachibana/立花交易计划_YYYY-MM-DD.xlsx`
- Sheet 1 "今晚交易计划"：代码、名称、决策、z值、梯①②③价、止损价、上沿价、股数、风险预算
- Sheet 2 "跟踪池"：现有跟踪池全部持仓状态

**理论溯源：**
- 立花义正《你也可以成为股票操作高手》
- G0资产：1975-1976交易谱数字化（159笔，100%通过恒等式）
- G4验证：浪识别不可完全量化，但梯价结构、仓位规则已验证

#### 2.2.4 成交录入（CLI工具）

**使用场景：** 用户看Excel后在券商APP挂单，次日成交后录入系统

**命令格式：**
```bash
tb-cli record buy \
  --code 600519 \
  --price 1850.0 \
  --qty 100 \
  --note "梯①" \
  --date 2026-10-09

tb-cli record sell \
  --code 600519 \
  --price 1920.0 \
  --qty 100 \
  --note "止盈" \
  --date 2026-10-10
```

**存储位置：** `transactions` 表

**自动计算：**
- 滑点% = (实际成交价 - 计划价) / 计划价
- 手续费（暂按万2.5，可配置）
- 成交金额

#### 2.2.5 每日复盘（Review）

**执行时间：** 每日 15:30（收盘后）  
**功能：**

**1. 跟踪池更新**
```
遍历跟踪池所有active持仓：
  读取当日日K线
  
  检查成交：最低价 ≤ 梯价 → 标记filled（需人工确认）
  检查止损：最低价 ≤ 止损价 → 标记stopped + 警报
  检查止盈：最高价 ≥ 上沿价 → 推送提醒
  检查过期：无成交天数 ≥ 40 → 标记expired
  
  更新last_update = 今日
```

**2. 复盘报告生成**
```
汇总当日成交：
  - 成交笔数
  - 平均滑点%
  - 止损触发次数

账本校验：
  权益 = 现金 + 持仓市值
  检查恒等式：今日权益 = 昨日权益 + 今日损益 - 手续费

日收益率：
  (今日权益 - 昨日权益) / 昨日权益

警示项：
  - 跌停未止损
  - 滑点异常（>2%）
  - 连续止损（≥3次）
```

**输出格式：**
- Excel/Markdown：`reports/review/复盘_YYYY-MM-DD.xlsx`
- 更新 `reviews` 表

## 三、非功能需求

### 3.1 性能需求

| 场景 | 指标 | 说明 |
|------|------|------|
| 19:00初选 | < 3分钟 | 全市场5000+只股票 |
| 19:30生命周期 | < 2分钟 | 处理30-50只股票 |
| 20:00交易计划 | < 1分钟 | 生成计划+更新跟踪池 |
| 15:30复盘 | < 30秒 | 更新跟踪池+生成报告 |
| CLI成交录入 | < 1秒 | 实时响应 |
| GUI启动 | < 2秒 | 桌面应用冷启动 |

### 3.2 可靠性需求

**数据一致性：**
- 数据库事务保证
- 账本恒等式每日校验
- 关键操作失败回滚

**容错性：**
- 数据源失败降级（TDX → 腾讯 → 新浪）
- 单只股票数据异常不影响整体任务
- 网络超时自动重试（最多3次）

**审计性：**
- 所有任务执行记录到 `job_runs` 表
- 成交记录永久保存
- 跟踪池状态变更日志

### 3.3 可用性需求

**易用性：**
- 单文件打包，拷贝即用
- 配置文件YAML格式，注释完整
- CLI命令遵循Unix风格（`tb-cli <verb> <noun> --flags`）
- GUI操作不超过3次点击

**可维护性：**
- 代码模块化，职责清晰
- 关键算法附原著引用
- 错误信息包含上下文和建议

**可移植性：**
- 纯Go实现，无CGO依赖
- 支持Windows/Linux/macOS
- 数据库SQLite，单文件便携

### 3.4 安全需求

**数据隐私：**
- 所有数据本地存储
- 不上传交易记录到云端
- 配置文件不包含敏感凭证

**风控边界：**
- 仓位上限硬编码（单股20万，总风险1%）
- 止损距离不得小于0.5×ATR
- 日内亏损超过阈值时警报

## 四、约束条件

### 4.1 技术约束

- Go 1.22+ 必需
- SQLite作为唯一数据库
- 不依赖外部服务（除数据源API）
- 第一期不含实盘API对接（人工执行）

### 4.2 业务约束

- 仅支持A股市场（沪深主板/创业板/科创板，不含北交所）
- 仅做多（无融券做空）
- T+1交易制度
- 涨跌停限制（主板/科创板10%，创业板/ST 20%/5%）

### 4.3 数据约束

- 历史数据依赖通达信（最早可至上市日）
- 概率表基于2016-2021训练数据（偏熊市，概率保守）
- 退市股未纳入统计（存活概率偏高）

### 4.4 法律约束

- 系统输出仅作研究参考，不构成投资建议
- 不提供代客理财功能
- 不提供实盘自动下单（第一期）

| z值 | 标准化回档深度：(MA20-现价)/ATR14 |
| 梯价 | 立花分批买入的三个价格档位 |
| 跟踪池 | 已生成交易计划但尚未完全成交的持仓列表 |
| 账本恒等式 | 权益 = 现金 + 持仓市值 |
| Golden test | 用已知正确结果验证新实现 |
