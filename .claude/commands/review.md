# Go 代码审查清单

审查以下代码的质量和规范性：

**审查目标：** $ARGUMENTS

## 检查项

### 1. 代码规范
- [ ] gofmt格式是否正确
- [ ] 命名是否符合Go惯例（驼峰式，不使用下划线）
- [ ] 导出函数是否有文档注释
- [ ] 注释是否完整且准确

### 2. 错误处理
- [ ] 是否正确传播error
- [ ] 是否避免使用panic（除非真的不可恢复）
- [ ] 是否有合适的错误上下文信息
- [ ] 资源是否正确释放（defer）

### 3. 性能考虑
- [ ] 是否有不必要的内存分配
- [ ] 字符串拼接是否使用strings.Builder
- [ ] 是否有goroutine泄漏风险
- [ ] 数据库连接是否正确关闭

### 4. 安全性
- [ ] SQL是否使用参数化查询（防注入）
- [ ] 用户输入是否验证
- [ ] 是否有路径遍历风险
- [ ] 敏感数据是否明文存储

### 5. 测试覆盖
- [ ] 是否有单元测试
- [ ] 边界条件是否测试
- [ ] 错误路径是否测试

### 6. 项目特定
- [ ] 关键算法是否附原著引用
- [ ] 统计概率是否附样本量和置信区间
- [ ] 是否符合TradeBuddy编码规范（见CLAUDE.md）

## 输出格式

对每个问题，提供：
1. 问题描述
2. 所在位置（文件:行号）
3. 严重程度（高/中/低）
4. 修复建议

审查完成后给出总体评分（A/B/C/D）和改进建议。
